### SN-BTY-035

<a id="sn-bty-035"></a>

**Define per-script beautification tiers and default unvalidated scripts to off**

| Field | Value |
|---|---|
| GitHub | #1129 |
| Type | feature |
| Priority | p1 |
| Milestone | M3 Audio & Recognition |
| Platforms | all |
| Areas | i18n, ocr-hwr, settings |
| Size | L |
| SDLC | implementation |
| Parent | [SN-BTY-001](ocr-hwr.md#sn-bty-001) |
| Depends on | [SN-HWR-003](ocr-hwr.md#sn-hwr-003), [SN-I18N-001](i18n.md#sn-i18n-001) |
| Security controls | `MASVS-PRIVACY-1`, `OWASP-A04`, `ASVS-V1`, `CWE-451`, `CWE-117`, `TM-I-05` |
| Extra labels | agent-ready |

#### Context
Sane Notes targets India first — Hindi, Marathi, Tamil, Bengali, Gujarati — and ships Arabic RTL and CJK support (locked decision 10). Every technique in [SN-BTY-001](ocr-hwr.md#sn-bty-001) was designed against Latin script and **will corrupt other scripts if applied naively**. Devanagari hangs its glyphs from a shirorekha headline with matras above and below, so fitting a baseline to glyph bottoms or splitting an akshara into "letters" destroys it. Arabic joins contextually, so cutting a word into glyph exemplars and re-joining them produces letterforms that do not exist. Thai and Khmer have no inter-word spaces and stack marks vertically. CJK has thousands of classes and stroke-order semantics, so exemplar coverage is never reached. Nebo simply refuses RTL entirely (`docs/research/sources/samsung-notes-nebo-other.md` §Nebo). Our rule is narrower and safer: **beautifying a script we have not validated is OFF, not wrong.**

#### Scope
**In:** a `ScriptSupportTier` table keyed by ISO 15924 code, with a stated tier and a written rationale per entry; enforcement at every beautify entry point through one policy API; per-script enable/disable in Settings with an explicit experimental warning for below-default tiers; script-specific correctness invariants for the scripts we do support structurally; a validation corpus and CI gate per script; documentation of the table in the PRD and in user-facing help.
**Out:** per-block script and language detection ([SN-BTY-036](i18n.md#sn-bty-036)); recognition language packs ([SN-I18N-010](i18n.md#sn-i18n-010)); font fallback for typed text ([SN-I18N-008](i18n.md#sn-i18n-008)); the transforms themselves.

#### Acceptance criteria
- [ ] The table ships exactly four tiers and assigns every supported script to one. **Tier A — full** (structure, glyph synthesis, word-level spelling): Latin `Latn`. **Tier B — structure only** (straighten, align, reflow, snap; synthesis and per-word correction off): Devanagari `Deva`, Bengali `Beng`, Gujarati `Gujr`, Gurmukhi `Guru`, Tamil `Taml`, Telugu `Telu`, Kannada `Knda`, Malayalam `Mlym`, Odia `Orya`, Cyrillic `Cyrl`, Greek `Grek`. **Tier C — whole-selection straighten only** (no per-word edit, no reflow, no synthesis): Arabic `Arab`, Hebrew `Hebr`, Thai `Thai`, Han `Hani`, Hiragana `Hira`, Katakana `Kana`, Hangul `Hang`. **Tier D — off**: every script not listed.
- [ ] Tier D is the default branch in code: an unknown or unmapped script returns "no beautification available", asserted by a test that feeds an unmapped script code and expects refusal, never a Latin fallback.
- [ ] **Devanagari invariant:** baselines are fitted to the **shirorekha**, not to glyph bottoms; a straighten pass leaves matras and virama-formed conjuncts intact, verified by golden before/after images and by a recognition round-trip that must not change the recognised akshara sequence.
- [ ] **Arabic invariant:** no operation splits a word into glyph units or alters joining forms; RTL order is preserved and harakat offsets relative to their base letter change by 0 px; a straighten pass rotates and translates whole words only.
- [ ] **CJK invariant:** no synthesis (coverage is unreachable), no inter-word respacing (there are no word spaces); straighten operates on whole lines or columns and preserves the em-square relationship between adjacent glyphs.
- [ ] No operation ever splits a Unicode grapheme cluster or reorders combining marks, enforced with UAX #29 boundaries and asserted on a corpus of Devanagari conjuncts, Tamil ligatures, Arabic joined forms, Thai stacks and ZWJ emoji.
- [ ] Settings shows per-script toggles with the tier in plain language; enabling a below-default capability requires confirming a warning, is stored per profile, and is never enabled by default or by an app update.
- [ ] Every tier assignment has a checked-in validation corpus of ≥ 50 pages, and CI fails if a beautify pass changes the recognised character sequence for any page in it.

#### Technical notes
`packages/sane_ml/lib/src/script/tiers.dart` — a `const` table mapping ISO 15924 codes to `ScriptSupportTier` with a dartdoc rationale per row, plus `ScriptPolicy.allows(operation, script)` that every beautify entry point must call. Script identity comes from the Unicode Script property (UAX #24) over recognised text and from the resolved recognition model, never from a language guess. Grapheme-cluster safety uses `package:characters` (Dart's UAX #29 implementation); add a Semgrep/lint rule banning code-unit indexing and `String.split('')` anywhere under `beautify/`, `synth/` and `spell/`. Bidi follows UAX #9 and the RTL groundwork of [SN-I18N-001](i18n.md#sn-i18n-001). Shirorekha detection — the topmost horizontal run per akshara cluster via a projection profile — is documented in `docs/architecture/ink-engine.md` beside the baseline fitter so [SN-BTY-004](ocr-hwr.md#sn-bty-004) uses the same definition.

#### Security & privacy
On-device (MASVS-PRIVACY-1), nothing logged (TM-I-05, CWE-117). This is fundamentally an **integrity and inclusion control** (OWASP-A04, CWE-451): silently mangling someone's Hindi notes is data corruption and a discriminatory failure, and an Indian student's notebook must not be where we discover that our baseline fitter assumed Latin descenders. The fail-safe default means an unsupported script produces no change rather than damage, and the per-script confirmation is informed consent for an experimental transformation of the user's own data.

#### UX notes
Settings → Handwriting → Beautify by script ([SN-SET-007](settings.md#sn-set-007)), listing the scripts the user actually writes in (from [SN-BTY-036](i18n.md#sn-bty-036)), each with a plain-language tier — "Devanagari: we straighten and align, but we don't rewrite words yet" — and an experimental toggle behind a warning sheet. Never present a lower tier as a defect of the user's language; the copy owns it as our limitation. Localised ([SN-I18N-001](i18n.md#sn-i18n-001)), RTL-correct in the settings screen itself, all 17 looks and dark, screen-reader labelled.

#### Test plan
`packages/sane_ml/test/script/tiers_test.dart` (every operation × every tier; unmapped script refuses), `packages/sane_ml/test/script/grapheme_safety_test.dart`, `app/test/i18n/beautify_devanagari_shirorekha_test.dart`, `app/test/i18n/beautify_arabic_invariants_test.dart`, `app/test/i18n/beautify_cjk_invariants_test.dart`, corpus gate `app/test/i18n/beautify_script_corpus_test.dart` with fixtures under `app/test/fixtures/scripts/`, golden `app/test/golden/beautify_script_*`, plus a test for the Semgrep rule banning code-unit indexing in beautify paths.

#### Dependencies
SN-HWR-003 (per-script recognition), SN-I18N-001 (RTL and Indic groundwork). Consumed by every other SN-BTY issue; pairs with [SN-BTY-036](i18n.md#sn-bty-036).

### SN-BTY-036

<a id="sn-bty-036"></a>

**Detect the script and language of each handwritten block for bilingual pages**

| Field | Value |
|---|---|
| GitHub | #1183 |
| Type | feature |
| Priority | p1 |
| Milestone | M3 Audio & Recognition |
| Platforms | core |
| Areas | i18n, ocr-hwr, ai |
| Size | M |
| SDLC | implementation |
| Parent | [SN-BTY-001](ocr-hwr.md#sn-bty-001) |
| Depends on | [SN-HWR-003](ocr-hwr.md#sn-hwr-003), [SN-BTY-003](ocr-hwr.md#sn-bty-003) |
| Security controls | `MASVS-PRIVACY-1`, `MASVS-PRIVACY-4`, `OWASP-A03`, `OWASP-A04`, `CWE-117`, `TM-I-05`, `TM-I-08`, `TM-P-02` |
| Extra labels | agent-ready, innovation |

#### Context
A real Indian student's page is bilingual: a Hindi definition, an English formula label, a Marathi heading, all on one sheet. Nebo allows exactly one recognition language per note (`docs/research/sources/samsung-notes-nebo-other.md` §Nebo) and Goodnotes sets spellcheck language per document — both get bilingual pages wrong. Beautification cannot afford that: applying English spelling rules to a Devanagari block, or Latin baseline fitting to an Arabic one, is precisely the corruption [SN-BTY-035](i18n.md#sn-bty-035) exists to prevent. The tier system therefore needs an input — **which script and language is each block of ink?** — so a single page can be beautified correctly block by block.

#### Scope
**In:** block-level **script** detection from ink features alone, before a recognition model is chosen (relative height of the densest horizontal run, since the Devanagari shirorekha sits at the top and the Latin baseline at the bottom; stroke count per cluster; aspect ratio; writing-progression direction for RTL; presence of below-base marks); block-level **language** identification from recognised text with a confidence; re-recognition of a block with the correct model when the first pass used the wrong one; a per-block `ScriptLanguageTag` written onto the recognition index; hysteresis so a block does not flip tags while it is being written; the fallback chain to notebook language then device locale; a per-page summary consumed by [SN-BTY-035](i18n.md#sn-bty-035)'s settings and by search.
**Out:** the tier policy ([SN-BTY-035](i18n.md#sn-bty-035)); block segmentation ([SN-BTY-003](ocr-hwr.md#sn-bty-003)); model download UX ([SN-I18N-010](i18n.md#sn-i18n-010)); translation ([SN-HWR-022](ocr-hwr.md#sn-hwr-022)).

#### Acceptance criteria
- [ ] Script detection from ink features reaches ≥ 95 % block accuracy on the bilingual fixture corpus (Devanagari/Latin, Tamil/Latin, Arabic/Latin, Han/Latin) **without** having recognised the text first.
- [ ] Language identification on recognised text reaches ≥ 90 % block accuracy across the supported language set, with a confidence floor below which the notebook language is used.
- [ ] A page with a Hindi paragraph and an English paragraph yields two differently tagged blocks, and one beautify pass applies Tier B behaviour to the Devanagari block and Tier A to the Latin block ([SN-BTY-035](i18n.md#sn-bty-035)).
- [ ] A single word never carries two tags; a mixed-script word such as a Latin acronym inside a Hindi sentence is tagged by its surrounding block and excluded from word-level correction.
- [ ] Detection adds ≤ 40 ms per page on a background isolate and is incremental — adding a line re-tags only its block.
- [ ] Hysteresis: a block's tag does not change while the user is actively writing in it, and changes only after ≥ 3 consecutive contradicting words.
- [ ] Where the recognition model for a detected script is not installed, the block is tagged `modelMissing`, beautification for it is skipped, and the download is offered ([SN-I18N-010](i18n.md#sn-i18n-010)) — never a wrong-model recognition result.
- [ ] Fully on-device apart from the explicit model download; asserted by test.

#### Technical notes
`packages/sane_ml/lib/src/script/detect.dart` (ink-feature script detector, pure Dart) and `lang_id.dart` (a wrapper over the language-identification capability exposed through [SN-HWR-002](ocr-hwr.md#sn-hwr-002): ML Kit Language Identification on mobile, `NLLanguageRecognizer` on Apple, a compact n-gram profile model on web). Blocks come from [SN-BTY-003](ocr-hwr.md#sn-bty-003); tags are stored on the recognition index rows built by [SN-HWR-006](ocr-hwr.md#sn-hwr-006) so search, spellcheck and beautify read one source of truth. ML Kit Digital Ink requires choosing a model per call, which is exactly why the ink-feature detector must run first; where the first pass used the wrong model, re-run once with the detected one and keep the higher-confidence result. Script codes are ISO 15924 and language tags BCP 47, matching [SN-BTY-035](i18n.md#sn-bty-035)'s table and [SN-I18N-001](i18n.md#sn-i18n-001)'s locale model.

#### Security & privacy
On-device (MASVS-PRIVACY-1); there is no cloud language-identification path (TM-I-08, OWASP-A03). Script and language tags are derived note content and are never logged or sent to telemetry, because **the set of languages a person writes in is sensitive personal information** that can reveal ethnicity, religion or migration status — GDPR special-category-adjacent and a LINDDUN identifiability risk (TM-P-02, CWE-117). Only a coarse, opt-in, language-free "beautify used" counter may exist ([SN-BTY-052](telemetry.md#sn-bty-052)). Tags are deleted with their notes (MASVS-PRIVACY-4). Downloaded models are integrity-checked before use (ADR-0016 §8).

#### UX notes
Mostly invisible; it shows up as "the right thing happened on a bilingual page". Surfaces: [SN-BTY-035](i18n.md#sn-bty-035)'s per-script settings list is populated from detected scripts, and the recognition-language picker ([SN-HWR-008](ocr-hwr.md#sn-hwr-008), [SN-I18N-010](i18n.md#sn-i18n-010)) shows "detected automatically" with a per-notebook manual override. The missing-model state offers the download with its size. Copy must never imply a language is unsupported when only the model is absent. Localised, RTL-correct, all looks and dark, screen-reader labelled.

#### Test plan
`packages/sane_ml/test/script/detect_test.dart` (per-script-pair accuracy, shirorekha-versus-baseline discrimination, RTL progression), `packages/sane_ml/test/script/lang_id_test.dart` (accuracy, confidence floor, fallback order), `packages/sane_ml/test/script/hysteresis_test.dart`, `app/test/i18n/bilingual_page_beautify_test.dart` (one pass, two tiers), `app/test/perf/script_detect_budget_test.dart`, `app/test/security/lang_id_no_network_test.dart`, fixtures under `app/test/fixtures/scripts/bilingual/`.

#### Dependencies
SN-BTY-003 (blocks to tag), SN-HWR-003 (recognition engine and models). Feeds [SN-BTY-035](i18n.md#sn-bty-035), [SN-BTY-026](ocr-hwr.md#sn-bty-026) and [SN-BTY-032](ocr-hwr.md#sn-bty-032).

#### Definition of done
- [ ] Code + tests merged, CI green (dart format, dart analyze --fatal-infos, arch-lint, unit/widget/golden, Semgrep, mobsfscan, gitleaks/trufflehog, OSV-Scanner, dependency-review)

### SN-GA11-003

<a id="sn-ga11-003"></a>

**Expose content language to assistive tech and speech (3.1.1, 3.1.2)**

| Field | Value |
|---|---|
| GitHub | #536 |
| Type | feature |
| Priority | p2 |
| Milestone | M3 Audio & Recognition |
| Platforms | all |
| Areas | i18n, a11y, ocr-hwr |
| Size | M |
| SDLC | implementation |
| Parent | [SN-I18N-001](i18n.md#sn-i18n-001) |
| Depends on | [SN-A11Y-004](a11y.md#sn-a11y-004), [SN-I18N-010](i18n.md#sn-i18n-010) |
| Security controls | `ASVS-V5-Validation` |
| Extra labels | agent-ready |

#### Context

`docs/design/accessibility.md` §11 requires OCR transcripts to be announced to screen readers and §7 requires Read Aloud, but nothing records **which language** a piece of content is in. WCAG 2.2 **3.1.1 Language of Page (A)** and **3.1.2 Language of Parts (AA)** are both in scope and both are currently unowned. The consequence is concrete and severe for our India-priority users: a Hindi handwriting transcript announced by an English VoiceOver voice is unintelligible, and an Arabic transcript read with an English voice is worse than silence. The same metadata drives Read Aloud voice selection in reading mode ([SN-A11Y-014](a11y.md#sn-a11y-014)), the correct hyphenation/line-breaking, and correct font fallback ([SN-I18N-008](i18n.md#sn-i18n-008)).

#### Scope

**In:** a `languageTag` (BCP-47) on typed-text blocks, ink stroke groups (from the recognition language used, [SN-I18N-010](i18n.md#sn-i18n-010)), images with alt text, audio transcripts, and the page as a whole (dominant language); propagation of that tag into the semantics layer (`Semantics(attributedLabel/localeIdentifier)` on iOS via `accessibilitySpeechLanguage`, Android `AccessibilityNodeInfo` extras / `LocaleSpan` on the content description, and `lang`/`dir` attributes on the web parallel DOM nodes and the document root); a documented fallback chain (object language → page language → notebook language → UI locale); Read Aloud voice selection keyed to the tag with a graceful fallback and an announced notice when no voice for that language is installed.

**Out:** translation ([SN-HWR-022](ocr-hwr.md#sn-hwr-022)), automatic language detection quality beyond the recogniser's own output, per-word language switching inside a single ink block.

#### Acceptance criteria

- [ ] Every accessible node exposes a language tag; the web parallel DOM carries `lang` and, for RTL content, `dir`.
- [ ] A Devanagari transcript is spoken with a Hindi voice by VoiceOver and TalkBack on a device with that voice installed.
- [ ] The document/root language follows the UI locale and updates live when the locale changes ([SN-I18N-011](i18n.md#sn-i18n-011)).
- [ ] Read Aloud picks the content-language voice; if unavailable it falls back, announces the fallback once, and links to the OS voice-download setting.
- [ ] Mixed-language pages announce each block in its own language, verified on a page containing English + Hindi + Arabic blocks.
- [ ] The tag is persisted in the document model and survives sync, export and import round-trips.

#### Technical notes

Add the field in `packages/sane_core` document model (a CRDT-safe scalar per object, defaulting to null = inherit). Platform channels: iOS `NSAttributedString` with `.accessibilitySpeechLanguage`; Android `SpannableString` with `LocaleSpan`; web via the parallel DOM node attributes built in [SN-WEB-021](a11y.md#sn-web-021). Flutter's `Semantics(attributedLabel:)` accepts locale-bearing attributed strings on iOS; where the framework cannot express it, use the platform channel already added for the custom rotor in [SN-A11Y-004](a11y.md#sn-a11y-004).

#### Security & privacy

Language is content-derived metadata: keep it inside the encrypted document envelope like any other content field ([SN-CRY-001](security.md#sn-cry-001)), never in cleartext filenames or sync metadata, since a language list is a sensitive inference about the user (LINDDUN: disclosure/identifiability). No network lookup for language detection.

#### UX notes

Invisible by default. The notebook language is shown (and overridable) in notebook settings next to the handwriting-recognition language; reading mode shows the detected language with a one-tap override.

#### Test plan

`packages/sane_core/test/document/language_tag_test.dart` (inheritance chain, persistence, round-trip); semantics golden per platform asserting the emitted language; a manual multi-language announcement matrix with VoiceOver/TalkBack/NVDA; Read Aloud fallback test with the voice uninstalled.

#### Dependencies

[SN-A11Y-004](a11y.md#sn-a11y-004), [SN-I18N-010](i18n.md#sn-i18n-010).

- [ ] Code + tests merged, CI green (lint, analyze, unit, security scans)
- [ ] Docs/ADR updated if behaviour or architecture changed

### SN-GA11-014

<a id="sn-ga11-014"></a>

**Make keyboard shortcuts work on non-Latin layouts and during IME composition**

| Field | Value |
|---|---|
| GitHub | #548 |
| Type | task |
| Priority | p2 |
| Milestone | M2 Library & Documents |
| Platforms | web, ipad, android-tablet |
| Areas | i18n, input-gestures, a11y |
| Size | M |
| SDLC | implementation |
| Parent | [SN-I18N-001](i18n.md#sn-i18n-001) |
| Depends on | [SN-A11Y-008](a11y.md#sn-a11y-008), [SN-ED-022](editor.md#sn-ed-022), [SN-I18N-009](i18n.md#sn-i18n-009) |
| Security controls | — |
| Extra labels | agent-ready |

#### Context

[SN-A11Y-008](a11y.md#sn-a11y-008) and [SN-ED-022](editor.md#sn-ed-022) give us single-key tool shortcuts (P/H/E/V/S/T/I/R) and a Cmd/Ctrl shortcut map, and [SN-I18N-009](i18n.md#sn-i18n-009) requires that composition events are never intercepted. What neither owns is the interaction between the two: **a shortcut map defined by character produces the wrong key on a non-QWERTY physical layout and can be unreachable on a non-Latin one.** On AZERTY, the QWERTY 'A' position yields 'Q'; on a Devanagari, Hangul or Cyrillic layout, pressing the physical 'P' key produces a non-Latin character and a character-based matcher never fires, so the pen tool becomes unreachable by keyboard for exactly the users our India-priority locales target. Conversely, a physical-key matcher that ignores IME state will steal keystrokes mid-composition and corrupt typed Hindi, Japanese or Korean text. Keyboard operability is a WCAG 2.1.1 requirement, so this is an accessibility defect as much as an i18n one.

#### Scope

**In:** converting the shortcut layer to match on **physical key codes** (`PhysicalKeyboardKey` / `KeyboardEvent.code`) for positional single-key tool shortcuts, while keeping **logical** matching for shortcuts users think of as characters (Cmd+Z, Cmd+C); suppressing all single-key shortcuts while a text field has focus or an IME composition is active (`TextInputClient.currentAutofillScope`/composing range, `KeyboardEvent.isComposing` on web, `compositionstart`/`compositionend`); a visible shortcut cheat sheet ([SN-ED-022](editor.md#sn-ed-022)) that renders the **label of the physical key on the user's layout** rather than a hard-coded letter; verification on AZERTY, QWERTZ, Dvorak, Devanagari InScript, Hangul 2-set, Japanese JIS and Pinyin layouts; a documented rule in `docs/design/gestures-and-shortcuts.md` stating which shortcuts are positional and which are logical.

**Out:** user-remappable shortcuts (backlog), the gesture map, on-screen keyboard behaviour on phones.

#### Acceptance criteria

- [ ] Every single-key tool shortcut fires from the same physical key position on AZERTY, QWERTZ, Dvorak, InScript, Hangul and JIS layouts.
- [ ] No shortcut fires while a text field is focused or while an IME composition is in progress; typed Hindi/Japanese/Korean text is never corrupted or truncated by a shortcut handler.
- [ ] Cmd/Ctrl combinations continue to match logically (Cmd+Z is undo regardless of layout).
- [ ] The cheat sheet displays the key label for the active layout, or the physical key name where the label is unavailable.
- [ ] An automated test drives synthetic key events for at least four layouts and asserts the resulting action.
- [ ] `gestures-and-shortcuts.md` documents the positional-vs-logical rule and the IME suppression rule.

#### Technical notes

Flutter: prefer `ShortcutActivator` implementations keyed on `PhysicalKeyboardKey` and a custom activator that consults an `ImeCompositionNotifier`. On web, Flutter's key data already carries `physicalKey` derived from `event.code`; verify `isComposing` is respected in the engine path and add a guard if not. Key labels can come from `KeyboardLayoutMap` (`navigator.keyboard.getLayoutMap()`) on Chromium, with the physical key name as fallback elsewhere.

#### Security & privacy

A keyboard-layout map is a fingerprinting signal: read it only for label rendering, never persist it, and never send it to telemetry ([SN-TEL-001](telemetry.md#sn-tel-001)). Ensure the key handler cannot be driven by document content (a malicious shared note must not synthesise shortcuts).

#### UX notes

Cheat sheet reference: `screens-and-flows.md` §7 and `gestures-and-shortcuts.md` §6. Where a label cannot be resolved, show the physical position name (for example 'key P position') rather than a misleading letter.

#### Test plan

`app/test/features/editor/shortcuts_layout_test.dart` (synthetic events per layout, IME suppression, logical combos); `app/integration_test/i18n/ime_shortcut_test.dart` typing Hindi and Japanese into a text object with shortcuts bound; manual pass with a physical AZERTY keyboard and an InScript layout.

| Priority | p2 |
| Milestone | M2 Library & Documents |
| Platforms | all |

#### Context

[SN-I18N-007](i18n.md#sn-i18n-007) mirrors chrome for RTL locales and [SN-I18N-002](i18n.md#sn-i18n-002) sets up ARB messages, but neither handles what happens when **user content of one direction is interpolated into a UI string of another** — which is most of our chrome: 'Delete {notebook}?', '{name} shared {notebook}', 'match: {snippet}', 'page {n} of {m}', file names in export toasts, tags, and collaborator names. Without explicit isolation, the Unicode bidi algorithm lets an Arabic notebook title reorder the surrounding English sentence (and vice versa), producing text that reads as a different sentence — a legibility bug and a spoofing vector, since RLO/LRO override characters in a shared note title or a collaborator's display name can visually reverse a destructive confirmation ('Delete' rendered after the name) or disguise a file extension. Accessibility is affected too: screen readers announce isolated runs with the right direction and voice.

#### Scope

**In:** a `SaneBidi` helper that wraps every interpolated user-supplied value in isolation marks (FSI...PDI, or `Directionality`/`Unicode.FSI` in Flutter text spans) at the formatting boundary, applied by default in the localisation accessor layer so callers cannot forget; stripping or neutralising the explicit override characters (U+202A..U+202E, U+2066..U+2069) from titles, names, tags and filenames on input and at render; digit shaping policy — decide and document that numbers in UI chrome use the locale's default digit set via `intl` ([SN-I18N-005](i18n.md#sn-i18n-005)) and that user-entered digits are preserved as typed; verification that mixed-direction search result snippets highlight the correct range; correct `dir`/`textDirection` on web parallel-DOM nodes for content runs ([SN-GA11-003](i18n.md#sn-ga11-003)).

**Out:** RTL chrome mirroring ([SN-I18N-007](i18n.md#sn-i18n-007)), complex-script shaping ([SN-TXT-007](text.md#sn-txt-007)), the canvas, which is never mirrored.

#### Acceptance criteria

- [ ] Every ARB message with a placeholder renders its value isolated; a lint/test fails if a placeholder is interpolated without isolation.
- [ ] An Arabic notebook title inside an English confirmation sentence renders in the correct order, verified by golden images in both directions.
- [ ] Explicit bidi override characters in titles, display names, tags and export filenames are removed or rendered inert; a fuzz test covers this.
- [ ] Search snippets with mixed direction highlight the matched term at the correct visual position.
- [ ] Numbers in chrome follow the locale digit set; user-typed digits are preserved verbatim in content.
- [ ] Screen readers announce each isolated run with its own direction (spot-checked with VoiceOver Arabic and TalkBack Hindi).

#### Technical notes

Implement at `app/lib/l10n/` in a wrapper around `AppLocalizations` (or a generated extension) so every accessor isolates automatically; for `Text.rich` use `TextSpan`s carrying direction. Sanitisation belongs in the shared input-validation layer in `packages/sane_core` so sync, export and collaboration all inherit it. Export filenames additionally need path-safe normalisation ([SN-SHR-002](sharing-export.md#sn-shr-002)).

#### Security & privacy

This is a spoofing control, not only a layout fix: bidi overrides in shared-note titles and collaborator display names ([SN-COL-001](collaboration.md#sn-col-001)) can mislead a user into confirming a destructive or sharing action (STRIDE: spoofing; OWASP A03 injection-adjacent). Cover the sanitiser with the fuzz corpus ([SN-QA-013](qa.md#sn-qa-013)) and record the control in the threat model ([SN-SEC-001](security.md#sn-sec-001)).

#### UX notes

No visible affordance; correctness only. Where a title is sanitised, keep the original bytes in storage and sanitise at render, so the user's own text is never silently rewritten.

#### Test plan

`app/test/l10n/bidi_isolation_test.dart` (isolation applied, override stripping, digit policy); goldens for `ar` and `he`-style mixed strings across key screens; a fuzz case set in the shared corpus; manual screen-reader spot checks.

### SN-I18N-008

<a id="sn-i18n-008"></a>

**Bundle script fallback fonts for CJK, Indic and Arabic coverage**

| Field | Value |
|---|---|
| GitHub | #899 |
| Type | feature |
| Priority | p1 |
| Milestone | M2 Library & Documents |
| Platforms | all |
| Areas | i18n, design-system |
| Size | L |
| SDLC | implementation |
| Parent | [SN-I18N-001](i18n.md#sn-i18n-001) |
| Depends on | [SN-I18N-003](i18n.md#sn-i18n-003), [SN-DS-002](design-system.md#sn-ds-002) |
| Security controls | `MASVS-NETWORK-1`, `MASVS-CODE-3`, `MASVS-CODE-4`, `MASVS-PRIVACY-2`, `CWE-400` |
| Extra labels | agent-ready |

#### Context
Every one of the 17 looks binds its display/body typeface from a twelve-family Latin set — Newsreader, Karla, Manrope, Bricolage Grotesque, DM Sans, Space Grotesk, Playfair Display, Nunito, IBM Plex Mono, Syne, Rubik, Archivo (`docs/design/design-system.md` §2 "Font stacks (F)" and §4). **None of them contains a single Devanagari, Tamil, Telugu, Bengali, Gujarati, Kannada, Malayalam, Gurmukhi, Odia, CJK or Arabic glyph**, so the moment we ship Hindi, Japanese or Arabic every string renders as tofu boxes. PRD-CO-374 in `docs/product/prd-04-sharing-collaboration-ai-study-a11y-i18n.md` §9 requires "full CJK + Indic glyph coverage" with line-breaking tested, and `docs/research/sources/accessibility-i18n-and-inclusive-design.md` §11 ("CJK & complex-text input") states the same. This is also the *only* i18n defect the pseudo-locale gate ([SN-I18N-004](i18n.md#sn-i18n-004)) can surface but not fix, because that gate pads strings with Greek/Cyrillic/Indic glyphs precisely to expose missing coverage. The app must work offline (locked decision 3), so fallbacks are bundled assets — `design-system.md` §8 already requires the look fonts to "resolve offline". Flutter web/CanvasKit makes this urgent: CanvasKit does **not** silently fall back to installed system fonts the way the browser does for DOM text, so an un-declared script is guaranteed tofu on web.

#### Scope
**In:** choose one fallback family per script — Noto Sans Devanagari, Tamil, Telugu, Bengali, Gujarati, Kannada, Malayalam, Gurmukhi, Oriya; Noto Sans CJK SC / TC / JP / KR; Noto Naskh Arabic (all SIL OFL, matching the licence posture of the look fonts); register them as `fontFamilyFallback` on the `SaneText` type scale so the look's Latin family always wins for Latin runs and the script font only fills gaps; subset/compress and enforce a download-size budget; on web emit `@font-face` with `unicode-range` so a visitor only downloads the ranges they actually render; ship CJK as an on-demand/deferred asset where the platform supports it (Play Asset Delivery / web deferred load) rather than in the base install; a tofu-detector test; licence + attribution rows in the About/licences screen and the release SBOM.
**Out:** the look font registration itself (design-system epic), the dyslexia reading fonts OpenDyslexic/Lexend (accessibility epic [SN-A11Y-001](a11y.md#sn-a11y-001)), handwritten ink (vector strokes, not text), and PDF-embedded fonts (owned by [SN-PDF-001](pdf.md#sn-pdf-001)).

#### Acceptance criteria
- [ ] A sample sentence in each of Hindi, Tamil, Telugu, Bengali, Gujarati, Kannada, Malayalam, Punjabi, Odia, Japanese, Korean, Simplified Chinese, Traditional Chinese and Arabic renders with **zero `.notdef`/tofu glyphs** in every one of the 17 looks, light and dark.
- [ ] Latin text is unchanged: a look's display/body family still renders Latin runs (golden diff against the pre-change baseline is empty for `en`).
- [ ] Bundled font payload adds **≤ 12 MB** to the base Android download and **≤ 12 MB** to the iOS install after subsetting/compression; CJK faces beyond the user's locale are delivered on demand, and CI fails if the budget is exceeded.
- [ ] On web, the first paint of the English app downloads **no** script font; loading a Hindi page fetches only the Devanagari range; cached cold start stays < 3 s (locked decision 7).
- [ ] Mixed-script text in one paragraph (e.g. `Physics II — तरंगें (波)`) shapes correctly with no baseline jump > 1 px and no clipped ascenders/descenders at Display XL (38/1.08) and Body (14/1.45) from `design-system.md` §3.
- [ ] A font that fails to load degrades to the platform system font and logs a warning containing only the family name and script tag — never text content.
- [ ] Text still scales to 200 % and honours the 1.4.12 spacing overrides with the fallback family active (no clipping).

#### Technical notes
Implement in `packages/sane_ui`: extend the `SaneText` widget and the resolved `fd`/`fb` families from the token `ThemeExtension` ([SN-DS-002](design-system.md#sn-ds-002)) to always append a script-fallback list via `TextStyle.fontFamilyFallback`. Assets live under `packages/sane_ui/assets/fonts/` and are declared in `packages/sane_ui/pubspec.yaml`; `sane_ui` stays a pure leaf (`docs/architecture/overview.md` §5) so no model/feature package is imported. For web, follow `docs/platform/web.md` and [ADR-0010](docs/adr/0010-web-pwa-strategy.md): CanvasKit resolves fonts from the declared asset manifest only, so every fallback must be declared; use deferred loading keyed off the resolved locale from [SN-I18N-003](i18n.md#sn-i18n-003). Prefer variable/static subsets over full faces; script fonts carry no italic — synthesise nothing, let the shaper handle it. Fallback order matters: put the look family first, then the script font for the active locale, then the remaining scripts, so a shared CJK codepoint resolves to the user's own regional variant (the classic Han-unification trap — `zh-Hans` must not render with the JP face). Implements PRD-CO-374.

#### Security & privacy
- **Egress / tracking:** fetching fonts from a third-party CDN (Google Fonts et al.) would be an undeclared network egress and would leak the user's IP, locale and referer to a third party on every launch. Fonts are therefore **bundled, or fetched only from our own signed asset bundle over TLS 1.2+ with a hash check** — no new egress without an ADR + threat-model row (CLAUDE.md §7.4; MASVS-NETWORK-1, MASVS-PRIVACY-2).
- **Untrusted binary parsing:** font files are a historical memory-safety surface. We never write a parser; shaping goes through the platform/Skia stack, and downloaded packs are integrity-verified before registration (MASVS-CODE-4).
- **Resource exhaustion:** on-demand font downloads are size-capped and disk-quota-checked before write, and are cancellable, so a hostile or broken CDN response cannot fill the device (CWE-400).
- **Supply chain / licensing:** every face is SIL OFL, recorded with its version and licence in the SBOM and the in-app licences screen (MASVS-CODE-3).
- Baseline: no note content, ink coordinates, or PII in logs — font diagnostics log family names and script tags only.

#### UX notes
The fallback must feel deliberate, not accidental. Per `docs/design/design-system.md` §3 the type scale (Display XL/L/M/S, Body, Body strong, Muted, Label, Mono) is fixed and only the *family* swaps per look — keep every size, weight, line-height and tracking when the script font takes over, so vertical rhythm is preserved even though an Indic or CJK heading cannot carry a look's serif personality (Paper, Editorial, Skeuomorphism). States: while a deferred web font is loading, render with the system fallback rather than blank text (no FOIT); on failure, show the text, never a tofu box. a11y: substitution must not change announced text; targets stay ≥ 44 pt (iPadOS) / 48 dp (Android) / 24 CSS px (web); contrast tokens are unchanged.

### SN-I18N-009

<a id="sn-i18n-009"></a>

**Support platform IMEs and complex-text editing in every text field**

| Field | Value |
|---|---|
| GitHub | #900 |
| Type | feature |
| Priority | p1 |
| Milestone | M2 Library & Documents |
| Platforms | all |
| Areas | i18n, text |
| Size | M |
| SDLC | implementation |
| Parent | [SN-I18N-001](i18n.md#sn-i18n-001) |
| Depends on | [SN-I18N-003](i18n.md#sn-i18n-003), [SN-TXT-001](text.md#sn-txt-001) |
| Security controls | `MASVS-PLATFORM-2`, `MASVS-PLATFORM-3`, `MASVS-PRIVACY-3`, `CWE-20` |
| Extra labels | agent-ready |

#### Context
Half of Sane Notes' locked locales cannot be typed without an input method editor: Chinese (Pinyin/Zhuyin), Japanese (Kana→Kanji conversion) and Korean (Hangul jamo composition) all commit text through multi-keystroke *composition* sessions, and Indic scripts compose multi-codepoint grapheme clusters (conjuncts like `क्षि`) that must move, select and delete as single units. PRD-CO-374 in `docs/product/prd-04-sharing-collaboration-ai-study-a11y-i18n.md` §9 requires platform IMEs to work "in all fields without intercepting composition events", and `docs/research/sources/accessibility-i18n-and-inclusive-design.md` §11 ("CJK & complex-text input") names the same three IME families plus line-breaking as the risk. The trap for a pen-first app is that our editor is full of raw key handling — keyboard shortcuts (`docs/design/gestures-and-shortcuts.md`), a lasso/tool state machine, and a text tool — and any of those swallowing Enter, Escape, Space or arrow keys during an active composition will corrupt or silently drop the user's input. This issue makes every typed surface IME-correct before the text tool ships in M2 (`docs/roadmap.md` M2 "Typed text tool + rich text").

#### Scope
**In:** audit and fix every typed surface — the typed-text object in the editor, notebook/page titles and rename dialogs, the search field and "Ask my notes" input, tags, comment composer, invite-by-email, and settings fields; guarantee composition (`TextInputClient` / `composing` range) is never intercepted by shortcut handling; grapheme-cluster-correct caret movement, selection extension, and backspace/delete using `characters`; correct line-breaking for CJK (no inter-word spaces) and non-breaking within Indic clusters; IME candidate-window placement not obscured by the palette dock or overlays; interplay with Apple Scribble (`plugins/sane_scribble`) so handwriting-into-field and IME composition do not fight; keyboard-cache suppression on secret fields.
**Out:** the rich-text model and typed-text rendering itself ([SN-TXT-001](text.md#sn-txt-001)), handwriting recognition of Indic/CJK ink ([SN-I18N-010](i18n.md#sn-i18n-010)), script font coverage ([SN-I18N-008](i18n.md#sn-i18n-008)), and the on-screen ink-to-text conversion UX ([SN-HWR-001](ocr-hwr.md#sn-hwr-001)).

#### Acceptance criteria
- [ ] Typing `ni hao` → selecting a candidate → Enter in the typed-text block, the notebook title, the search field and the comment composer commits `你好` exactly once, with the pre-commit composing text visibly underlined and **not** persisted to the document model until commit.
- [ ] A committed IME session is **one** undo step, not one step per keystroke (verified against the undo model [SN-ED-001](editor.md#sn-ed-001)).
- [ ] While a composition is active, Enter/Escape/Space/arrow keys reach the IME and are **not** consumed by editor shortcuts or the tool state machine; pressing Escape cancels the composition and returns focus, with no keyboard trap (WCAG 2.1.2).
- [ ] Backspace over `क्षि` deletes one grapheme cluster; backspace over a ZWJ emoji family (`👨‍👩‍👧`) deletes the whole cluster; left/right arrow and shift-selection move by grapheme cluster, never by code unit.
- [ ] A CJK paragraph wraps without splitting inside a run of Latin/number text, and an Indic paragraph never breaks inside a conjunct cluster.
- [ ] The IME candidate window is never covered by the palette dock, page rail, audio bar or an overlay in any dock position (Bottom/Top/Left/Right, design Settings §12 `dock`).
- [ ] Secret fields (passphrase, recovery code, OTP) set `autocorrect: false` and `enableSuggestions: false` so the platform keyboard does not learn or cache them.
- [ ] All of the above pass on iPadOS, Android and Chrome/Safari web (Flutter web text-input path), and on a phone-width layout (~400 px).

#### Technical notes
Work spans `app/lib/` text surfaces and the text primitives in `packages/sane_ui` (`SaneTextField` from the design-system component set) plus the typed-text editing path in `packages/sane_core`'s rich-text CRDT ([ADR-0005](docs/adr/0005-document-model-and-crdt.md); Peritext/Yjs-style per CLAUDE.md §2.4). Key rules: never mutate the document model from the *composing* range — only from `TextEditingValue` commits, otherwise a CRDT op is emitted per keystroke and sync/undo both degrade. Route shortcut handling through Flutter's `Shortcuts`/`Actions` with a guard on `TextEditingValue.composing.isValid` so the editor's key handlers stand down during composition; the editor canvas uses a raw `Listener` for pointers (CLAUDE.md §8) but keyboard must go through the focus system so IME wins. Use `package:characters` (`String.characters`) for every caret/selection/delete operation — never `String.length` or `substring` on code units. For Scribble, `plugins/sane_scribble` (see [ADR-0012](docs/adr/0012-native-plugin-strategy.md)) must relinquish the input connection before an IME session starts. Implements PRD-CO-374; complements the locale resolution in [SN-I18N-003](i18n.md#sn-i18n-003).

#### Security & privacy
- **Keyboard caching of secrets (MASVS-PLATFORM-3, MASVS-PRIVACY-3):** third-party IMEs receive every keystroke and many sync learned text to their own cloud. Passphrase, recovery-code and OTP fields must disable autocorrect/suggestions and use an appropriate `keyboardType`/`obscureText` so the platform does not persist them; this matches the `LEAK` requirements in PRD-03 and the clipboard/screenshot-protection posture.
- **Untrusted input (CWE-20):** committed IME text is untrusted like any other text — validate length and normalise (NFC) before it enters the document model or the FTS index, and never build a query string by concatenation.
- **Bidi / homoglyph spoofing:** text arriving from an IME or paste may carry bidi control characters; reuse the sanitiser from [SN-I18N-007](i18n.md#sn-i18n-007) when rendering it in chrome (comment previews, search snippets) so it cannot visually spoof UI (MASVS-PLATFORM-2).
- Baseline: no note content or keystrokes in logs — IME diagnostics log only state transitions and the active locale tag.

#### UX notes
The composing run renders with the platform's underline convention using design tokens (`--ac` accent underline, `docs/design/design-system.md` §4 palette keys) rather than a hard-coded colour, so it reads correctly in all 17 looks and in dark mode. Candidate-window collision is a real risk in this design: the palette dock floats over the canvas and is dockable to any edge (design §7.3 and Settings §12 "Toolbar position"), so the text caret must scroll into a safe area when an IME opens, exactly as it does for the software keyboard. Empty/error states: if the platform reports no input connection (web without focus), show the field's placeholder and do not swallow keystrokes. a11y: composition changes are announced via `SemanticsService.announce` so VoiceOver/TalkBack users hear candidate commits; focus order and the 44 pt / 48 dp / 24 CSS px target minima are unchanged; on web every field stays keyboard-reachable with a visible focus ring (≥ 2 px, ≥ 3:1).

#### Test plan
- Widget: `app/test/text/ime_composition_test.dart` — simulate `TextInputClient.updateEditingValue` with composing ranges for Pinyin, Kana→Kanji and Hangul; assert one commit, one undo step, and no model writes during composition.
- Unit: `app/test/l10n/grapheme_cluster_test.dart` — caret movement, selection and delete across Devanagari conjuncts, Tamil clusters and ZWJ emoji.
- Unit: `app/test/text/line_break_test.dart` — CJK and Indic wrapping cases.
- Widget: `app/test/text/shortcut_composition_guard_test.dart` — Enter/Escape are not consumed while composing.
- Integration: `app/integration_test/ime_fields_test.dart` — drive every typed surface on iPadOS/Android/web.
- Manual: real Pinyin, Kana and Hangul IMEs on device plus Apple Scribble into a text field.

#### Dependencies
[SN-I18N-003](i18n.md#sn-i18n-003) (supported locales + resolution), [SN-TXT-001](text.md#sn-txt-001) (typed text tool and rich-text model). Composes with [SN-ED-001](editor.md#sn-ed-001) (undo grouping) and [SN-I18N-007](i18n.md#sn-i18n-007) (bidi sanitisation).

#### Technical notes

#### Security & privacy

Your notes never change." — which also states PRD-CO-377 in-product. Ordering: "Use device language" first, then the best device match, then alphabetical by native name. Must render correctly in all 17 looks, light and dark, at phone width (~400 px) and RTL. a11y: `Semantics` label "Hindi, हिन्दी, partially translated, selected"; `SemanticsService.announce` on change ("Language changed to Hindi"); the live rebuild must not steal focus.

### SN-I18N-012

<a id="sn-i18n-012"></a>

**Establish the translation workflow, glossary and linguistic QA gate**

| Field | Value |
|---|---|
| GitHub | #903 |
| Type | task |
| Priority | p2 |
| Milestone | M7 Beta Hardening & Security Audit |
| Platforms | all |
| Areas | i18n, docs, qa |
| Size | M |
| SDLC | maintenance |
| Parent | [SN-I18N-001](i18n.md#sn-i18n-001) |
| Depends on | [SN-I18N-002](i18n.md#sn-i18n-002), [SN-I18N-004](i18n.md#sn-i18n-004) |
| Security controls | `MASVS-PRIVACY-4`, `MASVS-CODE-3`, `OWASP-A08`, `CWE-1007`, `CWE-134` |
| Extra labels | agent-ready, needs-decision |

#### Context
The ARB pipeline ([SN-I18N-002](i18n.md#sn-i18n-002)) gives us *slots* for translations; it does not give us translations, nor a way to keep them correct as the product changes. PRD-CO-371 makes an empty `untranslated-messages` report a release condition and PRD-04 §11.4 DoD item 4 makes the pseudo-locale gate plus real Indic coverage part of "done", so the project needs a repeatable path from "a new string landed in `app_en.arb`" to "that string is translated, reviewed and shipped in 18 locales" — with a hard gate that stops a half-translated or format-broken locale from reaching users. `docs/research/sources/accessibility-i18n-and-inclusive-design.md` §11 specifies the mechanical half (typed placeholders, ICU plurals/select, `untranslated-messages-file` tracking); this issue adds the human half: context for translators, a glossary of terms that must never be translated, a string-freeze rhythm, and automated validation of everything that comes back. Localisation is cross-cutting and audited in M7 (`docs/roadmap.md` M7 "i18n/RTL audit"), which is where this workflow must already be running.

#### Scope
**In:** a written workflow in `docs/product/` or `docs/design/` covering string freeze per release, the export→translate→import loop, and who reviews what; export/import scripts (`tools/scripts/l10n_export.mjs`, `tools/scripts/l10n_import.mjs`) converting between ARB and the chosen vendor format; a mandatory `@description` (and `@placeholders` with `type`/`format`) for every message, enforced by a CI lint; a **glossary** of do-not-translate terms and of terms with a fixed translation; a **screenshot/context pack** so translators see where a string appears; automated validation of returned files (ICU syntax, placeholder set identity, no bidi control characters, no HTML/markup injection, length sanity); the release gate that fails when a release-blocking locale has untranslated keys; a linguistic QA checklist per locale.
**Out:** actually procuring translations (budget/vendor is a maintainer decision), the pseudo-locale gate itself ([SN-I18N-004](i18n.md#sn-i18n-004)), store-listing and marketing copy translation (owned by [SN-REL-001](release.md#sn-rel-001) and [SN-SITE-001](website.md#sn-site-001)), and user-content translation, which is an explicit Sage feature (PRD-CO-156, [SN-AI-001](ai.md#sn-ai-001)).

#### Acceptance criteria
- [ ] `docs/` contains a translation-workflow document a new contributor can follow end to end without asking a question.
- [ ] CI fails if any message in `app_en.arb` lacks an `@description`, or if any placeholder lacks a declared `type` (and a `format` where it is a date/number/currency).
- [ ] `tools/scripts/l10n_export.mjs` produces a vendor-ready bundle containing **only** UI strings, their descriptions, placeholder metadata and screenshot references — a reviewer can diff it and confirm no note content, no user data, no keys/tokens.
- [ ] `tools/scripts/l10n_import.mjs` rejects a returned file that: changes the placeholder set of a message, breaks ICU plural/select syntax, introduces bidi control characters (U+202A–U+202E, U+2066–U+2069), introduces raw HTML/markup where the source had none, or exceeds 300 % of the source length; each rejection names the message key and the reason.
- [ ] The glossary lists at least: **Sane Notes**, **Sane Sage**, `.sanenote`, `.sane`, **Pro**, **Free**, and the 17 look names, each marked translate / do-not-translate with a rationale.
- [ ] A release-blocking locale with a non-empty `untranslated.json` fails the release gate; a non-blocking locale warns instead, and the app shows its "Partially translated" badge ([SN-I18N-011](i18n.md#sn-i18n-011)).
- [ ] Running the import on a deliberately corrupted fixture produces a non-zero exit and no partial write to `lib/l10n/`.
- [ ] The linguistic QA checklist exists per locale and covers terminology, tone (`docs/design/ux-principles.md`), truncation, and number/date correctness.

#### Technical notes
Keep the source of truth in `app/lib/l10n/app_en.arb` and generated code out of translators' hands. The scripts are Node 22 ESM under `tools/scripts/`, matching the existing tooling convention (`scripts/validate-issues.mjs`, CLAUDE.md §11), and run in the same CI workflow as the other gates from [SN-CI-001](ci-cd.md#sn-ci-001). Validation must compare the *placeholder set* (names and types) rather than string equality, since word order legitimately changes; ICU parsing can reuse the same `intl` message parser the generator uses so a file that imports cleanly is guaranteed to `gen-l10n` cleanly. Screenshots for context are generated from the golden-test harness rather than captured by hand, so they refresh automatically. **Maintainer decision required (`needs-decision`):** (a) which translation platform/vendor is used — a managed service (Crowdin/Lokalise-class), a community workflow, or machine translation with human review; and (b) which locales are release-blocking for v1 versus "ship partially translated with the badge". Implement the neutral default meanwhile: plain ARB round-trip on disk, English + Hindi + Arabic release-blocking (they are the locales that exercise Indic shaping and RTL), everything else non-blocking. Implements PRD-CO-371 and supports PRD-04 §11.4.

#### Security & privacy
- **Third-party data exposure (MASVS-PRIVACY-4):** translators are outside the trust boundary. The export contains UI strings and metadata only — never note content, user names, emails, telemetry, or anything from a real user's device. The exporter enforces this structurally by reading only the template ARB, and the workflow doc states it as a rule; a threat-model row records the translator as an external actor.
- **Untrusted data returning into the build (OWASP-A08, integrity failures):** a translated ARB is input from outside the repo and is validated before merge — ICU syntax, placeholder identity, markup and length. An unvalidated translation can break a format string at runtime (CWE-134) or crash a screen in exactly one locale, which is a denial of service for those users.
- **Bidi / homoglyph spoofing (CWE-1007):** translated strings are rendered in security-relevant chrome (share roles, "data leaves device" indicator, permission dialogs); bidi overrides or confusable characters in a translation could misrepresent a security decision, so they are rejected at import.
- **No secrets in ARB (MASVS-CODE-3, CLAUDE.md §7.2):** the lint fails on anything resembling a key, token or URL with credentials in a message value.
- Baseline: no note content or PII in logs; the scripts log message keys and locale tags only.

#### UX notes
No new runtime screen; the user-visible consequences are indirect but real. The glossary protects brand surfaces: `SaneSageMark` and the "Sane Sage" name are trademarked/fixed-colour per `docs/design/design-system.md` §1 and must never be localised, while the 17 look names (Paper, Skeuomorphism, Retro, Minimalism, Glassmorphism, Flat, Material, Bento UI, Pop, Maximalism, Y2K, Cyberpunk, Neumorphism, Claymorphism, Brutalism, Neo-Brutalism, Editorial) are decided once and applied consistently across the Appearance tab, onboarding and the marketing site. Tone guidance for translators comes from `docs/design/ux-principles.md` and the preserved microcopy in `docs/design/screens-and-flows.md` §16 — short, calm, second-person, never scolding. Where a translation cannot fit (German compounds, Tamil expansion), the checklist instructs the translator to shorten rather than let the UI truncate, and the pseudo-locale gate ([SN-I18N-004](i18n.md#sn-i18n-004)) is the safety net. a11y: descriptions must also cover semantics-only strings (screen-reader labels, announcements) so those get translated too — they are invisible in screenshots and are the most commonly missed.

#### Test plan
- Unit: `tools/scripts/test/l10n_import_test.mjs` — fixtures for placeholder mismatch, broken ICU plural, bidi control injection, markup injection, over-length, and a clean file; assert exit codes and that no partial write occurs.
- Unit: `tools/scripts/test/l10n_export_test.mjs` — export contains only allowed fields; a planted "secret" or content-like value fails the scan.
- CI: the `@description`/placeholder-metadata lint runs on every PR touching `app/lib/l10n/`; the release gate runs on release branches.
- Manual: run a full export → hand-translate five strings into Hindi and Arabic → import → `flutter gen-l10n` → app renders them.

#### Dependencies
[SN-I18N-002](i18n.md#sn-i18n-002) (ARB pipeline and `untranslated-messages-file`), [SN-I18N-004](i18n.md#sn-i18n-004) (pseudo-locale gate is the layout safety net this workflow relies on), [SN-CI-001](ci-cd.md#sn-ci-001) (CI to host the lints and release gate). Blocked on a maintainer decision for the translation platform and the release-blocking locale set.

- [ ] Code + tests merged, CI green (lint, analyze, unit, ARB metadata lint, security scans)
- [ ] Docs/ADR updated if behaviour or architecture changed — the workflow document and glossary committed, and the translator recorded as an external actor in `docs/security/threat-model.md`

#### Context
`docs/roadmap.md` M7 makes it an exit criterion that "WCAG 2.2 AA met on all chrome; **every supported locale (incl. Arabic RTL) renders correctly**", and PRD-04 §11.4 DoD item 4 pairs the pseudo-locale gate with real end-to-end Devanagari plus one more Indic script. The automated gates we already have each cover one slice — [SN-I18N-004](i18n.md#sn-i18n-004) catches truncation and mirroring against synthetic strings, [SN-I18N-008](i18n.md#sn-i18n-008) catches missing glyphs, [SN-I18N-007](i18n.md#sn-i18n-007) pins the canvas LTR — but none of them proves that the *real* translated product looks right on a real device, in a real look, at a real text size. This issue is the human-plus-harness audit that closes the loop before beta, producing a signed-off report and a reusable matrix rather than a one-off eyeball pass. It is deliberately scheduled in M7 alongside the accessibility audit, since the two share screens, devices and many failure modes (truncation, focus order, target size).

#### Scope
**In:** define and run the audit matrix — supported locales × the key screens × representative looks × light/dark × device classes; a scripted capture harness built on the golden/integration infrastructure and `tools/device_lab`; automated checks over the captures (tofu/`.notdef` detection, overflow detection, mirrored-layout assertions for `ar`, digit-shape and date/number spot checks); a manual checklist for the things a machine cannot judge (does the Hindi heading read naturally at Display L, is the Arabic line-height comfortable, does the Japanese label break in a sensible place); filing and tracking the defects found; a written report in `docs/qa/` with pass/fail per cell and any accepted risks.
**Out:** fixing the defects (each becomes its own issue against the owning area), the WCAG/screen-reader audit ([SN-A11Y-001](a11y.md#sn-a11y-001)), performance soak ([SN-PERF-001](perf.md#sn-perf-001)), and the pentest.

#### Acceptance criteria
- [ ] The matrix covers at minimum: locales `en`, `hi`, `ta`, `bn`, `ar`, `ja`, `ko`, `zh-Hans`, `zh-Hant`, `de` (longest Latin expansion), `pt`; screens Login, Profiles, Onboarding, Library, Editor (all four dock positions), Templates overlay, Import PDF overlay, Share overlay, Search/Ask, Settings (all six tabs), Upgrade overlay (design `docs/design/screens-and-flows.md` §§3–13); looks — all 17 for at least one locale, and 5 representative looks (Paper, Minimalism, Glassmorphism, Brutalism, Editorial) for all locales; light + dark; device classes iPad (ProMotion), mid-range Android tablet, Chrome desktop web, iPhone, Android phone, and one foldable in both postures.
- [ ] **Zero** tofu glyphs across every capture (automated `.notdef` scan).
- [ ] **Zero** unresolved truncation/overflow defects at default text size, and none at 200 % text scaling on the screens WCAG 1.4.4 applies to.
- [ ] In `ar`, chrome mirrors on every captured screen while the canvas capture is pixel-identical to the `en` canvas capture (PRD-CO-372).
- [ ] Dates, numbers and ₹ prices are correct per locale in the captures (spot-checked against [SN-I18N-005](i18n.md#sn-i18n-005) and [SN-I18N-006](i18n.md#sn-i18n-006) expectations, including Indian lakh/crore grouping).
- [ ] Focus order in RTL follows visual order, and left-handed mode composed with `ar` does not double-flip the page rail (PRD-CO-337).
- [ ] Untrusted text containing bidi control characters, rendered into search snippets and comment previews, does not visually reorder surrounding UI (negative test).

- [ ] The harness is re-runnable by a single command and its captures are diffable, so the audit is cheap to repeat each release.

#### Technical notes
Build on the existing golden harness and `integration_test`/patrol setup from [SN-QA-001](qa.md#sn-qa-001) rather than a new framework: a driver enumerates the matrix, forces `MaterialApp.locale` and the look, pumps each route, and writes a capture plus a metadata JSON (locale, look, theme, device, screen). Automated scans run over the captures in `tools/scripts/`: a `.notdef` scan (reusing the tofu detector from [SN-I18N-008](i18n.md#sn-i18n-008)), an overflow scan (assert no `RenderFlex` overflow errors were recorded during the pump and no clipped text rects), and a mirroring assertion comparing `ar` captures against horizontally-flipped `en` captures for chrome regions only. Real devices come from `tools/device_lab` and `docs/platform/compatibility-matrix.md`; the web leg runs against Chrome desktop per `docs/platform/web.md`. Keep the canvas comparison separate from the chrome comparison so a legitimately-unmirrored canvas does not fail the mirroring check. Report lives in `docs/qa/i18n-rtl-audit-<release>.md`. Verifies PRD-CO-370/372/374/375/376 end to end.

#### Security & privacy
- **Bidi spoofing of security-relevant chrome (CWE-1007, MASVS-PLATFORM-2):** the audit explicitly exercises attacker-controlled text — an imported or shared page title, an OCR transcript, a collaborator's comment — containing U+202A–U+202E / U+2066–U+2069, and asserts the sanitiser from [SN-I18N-007](i18n.md#sn-i18n-007) prevents it from reordering or masking surrounding UI such as share-role labels or the "data leaves device" indicator.
- **Capture hygiene (MASVS-PRIVACY-1):** audit fixtures use synthetic notebooks only. No real user content, account, token or device identifier may appear in a capture committed to the repo or attached to a report; captures are reviewed before commit, and the device-lab accounts are test accounts.
- **No new egress:** the harness runs locally/in CI against local fixtures; it introduces no network call and therefore no threat-model change beyond the existing test infrastructure.
- Baseline: no note content or PII in logs; the harness logs locale/look/screen identifiers only.

#### UX notes
The audit is judged against the design source of truth: `design/Sane Notes.dc.html` screen composition, `docs/design/screens-and-flows.md` §§3–13 for each surface, and `docs/design/design-system.md` §3 for the fixed type scale (Display XL 38/1.08 through Label 11/.08em) and §4 for the 17 looks. Expect the worst results in the tight, typographic looks (Brutalism, Neo-Brutalism, Editorial, Y2K) with the most expansive locales (German compounds, Tamil and Malayalam expansion) and in the glass looks (Glassmorphism, Neumorphism, Claymorphism) where heavier Indic and Arabic strokes can lose contrast over a frosted backdrop — the design's frosted-glass rule requires note contrast to be maintained. Empty, loading, error and offline states must be captured too, not just the happy path: they contain the longest sentences in the product and are the most commonly untranslated. a11y overlaps to verify in passing: 44 pt / 48 dp / 24 CSS px targets survive longer labels, focus rings stay visible (≥ 2 px, ≥ 3:1), and text at 200 % still reflows at 320 CSS px.
