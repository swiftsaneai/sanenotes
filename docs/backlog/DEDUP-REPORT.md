# Backlog dedup & repair report

Hand-maintained log of cross-cutting backlog repairs (the per-area files and `README.md` in this
directory are generated by `scripts/render-issues.mjs`; this file is not).

## Milestone dependency repair

**Problem.** 56 `depends_on` edges pointed at a key scheduled in a *later* milestone than the issue
that declared them (`node scripts/validate-issues.mjs --warnings | grep "lands later"`). An agent or
developer working the tracker in milestone order (M0 → … → M8 → Backlog, per `issues/milestones.json`)
would deadlock: the work could not start in its own milestone because a dependency lands later.

**Result.** All 56 edges fixed across 52 issues; `node scripts/validate-issues.mjs` now exits 0 with
**0 errors and 0 warnings**. No new backward edge was introduced (each moved issue was checked against
its own dependents and dependencies). Fixes are grouped by the repair rule below.

Counts: **Rule 1 — 45 issues / 47 edges · Rule 2 — 3 issues / 4 edges · Rule 3 — 4 issues / 5 edges.**

---

### Rule 1 — the dependency was on an epic (or an early interface/contract); the edge was the bug

interface that lands early. Fixed by repointing to the specific child, or by removing the edge and
stating the contract (interface + a permissive stub) in the consumer's `## Technical notes` and
`## Dependencies`. **45 issues, 47 edges.**

### Ambiguous calls worth a second look

- **SN-LIB-023** (multi-profile library isolation, M2) is a *verification* issue whose mechanism
  (SN-AUTH-007 local profiles, SN-AUTH-013 partition) lands M4. Moving it to M4 was rejected because a
  published M2 dependent (SN-LIB-028) would then point backward; moving the owners to M2 was rejected
  because SN-AUTH-007 depends on SN-AUTH-002 (core identity, genuinely M4). It stays M2 wired against a
  single-profile stub, with full isolation verified when M4 lands — the least-bad option.
- **SN-AUD-024 / SN-REL-011 / SN-GOPS-013 / SN-REL-007** each keep a sub-check/sub-path that genuinely
  can only run once a later feature exists (encrypted sync M4, subscription disclosure M8, release SBOM
  M8, production rollout M8). The edge was removed and the deferred sub-scope documented rather than
  delaying the whole (mostly-earlier) issue.
